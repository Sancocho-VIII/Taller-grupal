**Complejidad computacional Big O:**
**Ejercicio 1:**
Complejidad constante.
Justificacion: Como el programa pide un maximo de 3 números enteros, en el peor de los casos la cantidad de operaciones va a ser constante. La suma de los 3 numeros, y la division para 3. Por lo tanto el numero de operaciones es constante en el peor de los casos.
**Ejercicio 2:**
Complejidad lineal.
Justificacion: En el peor de los casos el programa tendria que recorrer todos los elementos de la lista pero econtrar al menor y al mayor. El numero de operaciones aumenta segun el numero de datos de forma lineal.
**Ejercicio 3:**
Complejidad lineal.
Justificacion: El programa recorre toda la lista hasta encontrar el numero que el usuario quiere encontrar. En el peor de los casos, el programa tendria que recorrer toda la lista que aumenta segun el numero de elementos de forma lineal.
**Ejercicio 4:**
Complejidad cuadrática.
Justificacion: Segun el numero de datos en la lista estos se tienen que comparar con los demas y se elimina el termino menor para no tener que volver a operar con el. Esto depende de una n(n-1) lo cual es una operación cuadrática.
**Ejercicio 5:**
Complejidad logaritmica
Justificación: el numero de operaciones depende de el logaritmo en base 2 de el numero. Mientras crece el valor de n la cantidad de divisiones aumenta de forma logatirmica.
**Ejercicio 6:**
Complejidad cuadratica. 
Justificación: para n numero de datos el numero de operaciones necesarias va a estar dado por n**2, ya que cada dato ingresado este se compara consigo mismo y con los demás.
